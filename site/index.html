Data in and out of s3.pe.gov.br, in one line.

The same nine verbs in four languages for the S3 object store of Pernambuco, or any S3-style store. Credentials from the environment, format from the extension, every transfer signed, retried and checked.

Four editions, one behaviour

Pick the language of the project. Everything else is the same: defaults, signing, retries, integrity checks, log lines and error kinds. One repository, one version, one changelog.

The nine verbs

A key is s3://bucket/key, or a bare key when the bucket is configured. Nothing else to learn.

Rust and Go expose the same verbs (s3pe::read_s3, s3pe.ReadS3) and a Client for explicit settings; R has s3_config().

What happens in every call

The parts that make the difference between "it usually works" and "it worked, and we know it did".

01

Sign

AWS Signature V4 over the real SHA-256 of the payload. No unsigned payloads, no aws-chunked (Garage rejects it). The four signers reproduce the AWS documentation vector.

02

Retry

Connection failures and HTTP 429, 500, 502, 503, 504: three tries, 1 s then 2 s. Never on other 4xx.

03

Verify

After an upload the server's ETag against the local MD5; after a download the byte count and the MD5 of what arrived.

04

Report

One line per transfer, silenced with S3PE_QUIET=1. Errors are typed: not found, access denied, HTTP, transport, configuration, integrity.

🧪

Tested three ways

Each edition runs against a local fake S3 that recomputes and checks every signature, against the AWS documentation vector, and against s3.pe.gov.br itself when S3PE_TEST_BUCKET is set.

📄

Decisions on record

Why path-style, why our own signer, why no multipart yet: DESIGN.md keeps the reasons, D1 to D11.

Architecture

Four implementations, one specification, one store. The Python package is a binding on the Rust crate; R and Go are native. Each edition has its own page: R, Python, Rust, Go.

Configuration

Argument, then environment, then default. Two variables are enough on a machine that talks to s3.pe.gov.br.

~/.Renviron, .env or the shell

AWS_ACCESS_KEY_ID=GK...
AWS_SECRET_ACCESS_KEY=...
S3PE_BUCKET=iaempe                 # optional: bare keys
# S3PE_ENDPOINT=http://127.0.0.1:9003   inside the server

Never put the key in a script or a repository. Inside the condepe server the endpoint is local; from anywhere else the default https://s3.pe.gov.br applies.
